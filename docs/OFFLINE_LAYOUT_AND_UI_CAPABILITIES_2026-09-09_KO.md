# 게임 없는 레이아웃 편집 및 모드별 UI 조사

작성: 2026-09-09 / 작업 폴더: E:\AMS2 KRLEAGUE\AMS2KRLeague
기준: 0.5.1 소스 + 기존 gzip 업로드 작업. 이번 변경은 미커밋·미릴리스 상태다.

## 1. 구현한 기능과 사용법

프로그램 상태창에서 다음 버튼을 사용할 수 있다.

- **게임 없이 주행 UI 편집**: 순위 타워, 전후방 거리, 랩 타임, 세션 정보, 이벤트, 레이스 컨트롤, 텔레메트리, 속도계, 기어를 가상 데이터로 표시한다.
- **게임 없이 대기 UI 편집**: 대기 화면을 가상 참가자 수·세션·남은 시간으로 표시한다.
- 패널을 드래그하고 우측 하단 손잡이로 크기를 바꾼 뒤 **저장 후 잠금**을 누른다.
- 미리보기 종류를 바꾸면 이전 화면에서 편집한 배치부터 저장한다.
- 기존 **레이아웃 편집** 버튼도 표시 중인 게임 화면이 없으면 주행 미리보기로 진입한다.
- 꺼 둔 패널은 미리보기에서도 숨긴다. 편집할 패널의 체크를 켜면 된다.

별도 게임 실행이나 공유 메모리 연결이 필요 없다. 명시적인 미리보기 버튼은 상태창이 있는 모니터의 작업 영역을 기준으로 열린다. 다른 모니터에서 편집하려면 상태창을 해당 모니터로 이동한 뒤 버튼을 누른다. 작업 표시줄은 편집 영역에서 제외한다.

배치는 기존 `%LOCALAPPDATA%\AMS2KRLeague\overlay-layout.json`에 저장한다. 별도 미리보기 전용 설정을 만들지 않으며 게임 화면 크기에 맞춰 기존 방식으로 비율 적용한다. 게임과 편집 화면의 해상도·가로세로 비율이 다르면 최종 배치를 게임에서 한 번 확인하는 것이 좋다.

미리보기 중 실제 게임 화면이 갱신되어도 편집 기준 화면과 가상 표시를 바꾸지 않는다. 종료하면 가상 창을 숨기고 다음 정상 표시 주기에 실제 화면으로 복귀한다. 가상 값은 화면 표시에서만 생성하며 기록·업로드 엔진으로 전달하지 않는다.

## 2. 조사 범위와 확인 수준

현재 소스의 SHM v14 파서, 표시 조건, 화면 모델을 확인했다. 아래의 “추가 가능”은 **프로그램에서 읽는 필드 또는 기존 계산에 구현 근거가 있다**는 뜻이다. 각 리플레이 파일·온라인 관전 상태에서 게임이 값을 정상적으로 제공하는지는 실게임 검증 전이다.

현재 구현에는 다음 제한이 있다.

- `LocalParticipantResolver`는 `InGamePlaying`에서 유효한 관전 대상 인덱스·참가자·순위가 있는 경우만 허용한다.
- `MultiplayerWaitingOverlayController`는 세션 메뉴 대기와 일부 종료 전환에 대기 화면을 표시하고, 리플레이 상태에서는 숨긴다.
- `OverlayVisibilityController`는 게임이 전면에 있고 최소화되지 않은 경우만 표시한다.
- `LocalParticipantResolver`의 선택 기준은 이름과 달리 **현재 보고 있는 참가자 인덱스**다. 이를 사용자 계정 소유 차량의 증거로 사용해서는 안 된다.
- 관전자·방송용 전용 화면이나 별도 방송 출력 경로가 추가된 상태는 아니다.

리플레이를 뒤로 감거나 관전 대상을 바꾸면 기존의 “직전 프레임과 비교” 로직으로 가짜 추월·신기록 이벤트가 생길 수 있다. 리플레이 확장 시 시간 역행과 대상 변경을 처리하고, 재생 데이터를 실시간 경기 기록으로 업로드하지 않는 표시 경로가 필요하다.

## 4. 그대로 표시하거나 확정하면 안 되는 항목

| 참가자 전원의 준비 완료 여부, 서버 핑, 음성 채팅 상태 | 현재 파서·모델에 해당 정보가 없다. |

| 정확한 도로 경계 지도 | 차량 위치·주행 궤적과 실제 도로 경계는 다르다. 현재 읽는 모델에는 도로 경계 좌표가 없다. |
| 다음 경기 일정·대회 로고·해설자 이름 | 게임 텔레메트리 외의 웹 일정·방송 설정 자료가 필요하다. |

## 5. 다음 구현 순서 제안

1. **대기 화면 정보 확장**: 서킷·클래스·날씨·참가자 목록. 현재 대기 화면 경로를 활용할 수 있다.

3. **리플레이 표시 경로**: 리플레이 표식과 시간 역행 처리를 갖춘 뒤 대상 카드·계기판을 연결한다.
