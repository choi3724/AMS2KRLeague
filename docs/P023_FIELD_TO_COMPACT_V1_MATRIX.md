# P023 field to Compact Telemetry V1 migration matrix

## Contract and counting boundary

- This is a source-lineage and capture-policy matrix. Shipping high-rate Race Story, Replay, Driver, and Incident artifacts now use A2CT; `Registry status` distinguishes immutable schema coverage from the remaining low-rate session-metadata compatibility/routing HOLD.
- Exactly `161` header-useful inventory rows are listed in the useful-field table. `R008 mParticipantInfo[64]` is intentionally counted once as an `INTERNAL` container and consumes no standalone value bytes; its eight nested leaves are `P001-P008`. Therefore useful raw leaves are `160 / 160`.
- The five excluded header rows are in a separate table and are not silently folded into the useful count.
- P023 transport/helper values `sessionElapsedMs` and `capturedAtUnixMs` are not SHM inventory rows and are not binary value columns in Compact V1. Their migration representation is `IMPLICIT_HEADER_TIME`: `sessionElapsedMs` is reconstructed from `baseElapsedMs + cadence*index` or irregular elapsed deltas, while wall time is reconstructed from the attempt epoch/index metadata plus elapsed time. They add `0` field rows and `0` high-rate payload columns.
- `DCH.fieldOrdinal(ID)` is matrix shorthand for the immutable `TelemetryFieldCatalog.DriverTelemetryFields` ordinal associated with that SHM lineage; the wire contains the ordinal, never `ID` or a field name. A file-name suffix is not semantic protocol data.
- `SESSION_CHANGE_V1` now contains immutable `fieldOrdinal` plus `rawValue` at scale `0.001`. Typed string dictionaries are Event Type `1`, Event ID `2`, Fact Code `3`, Incident Candidate `4`, Incident Trigger `5`, Session Text `6`, and Driver Text `7`. Many low-rate session metadata strings/capabilities are still preserved losslessly in legacy JSON/gzip because the shipping adapter has not assigned complete typed session routing; this is a compatibility/HOLD condition, not missing source data.
- Every nullable numeric column uses the Compact presence bitmap. Source sentinels are translated only where the header defines their unavailable meaning; zero is otherwise retained as a real value.
- `Future feature` describes why the source remains in the contract. Reduced cadence is an explicit information policy, not deletion.

### Shipping `DRIVER_CHANGE_V1` policy

The shipping adapter applies the following policy before encoding the two-column DCH ordinal/value
schema. This policy, rather than the old 20 Hz P023 row rate, is authoritative for generic DCH facts:

- It inspects 31 discrete catalog fields at every input row and writes only transitions. The exact
  names are `driverRef`, `lap`, `sector`, `gearRaw`, `clutch`, `unfilteredClutch`, `pitStateRaw`,
  `lapValid`, `rootLapInvalidated`, `participantLapInvalidated`, `rootPitModeRaw`,
  `rootPitScheduleRaw`, `participantPitScheduleRaw`, `highestFlagColourRaw`, `highestFlagReasonRaw`,
  `participantHighestFlagColourRaw`, `participantHighestFlagReasonRaw`, `carFlagsRaw`,
  `antiLockActive`, `lastOpponentCollisionIndex`, `boostActive`, `drsStateRaw`, `antiLockSetting`,
  `tractionControlSetting`, `ersDeploymentModeRaw`, `ersAutoModeEnabled`, `clutchOverheated`,
  `clutchSlipping`, `launchStageRaw`, `handBrake`, and `crashStateRaw`.
- All non-dedicated, non-transition catalog fields are retained as 0.05 Hz (20-second) snapshots. The Server may
  derive coarse changes from those snapshots, but the contract does not claim every sub-20-second
  transient for that remainder. Continuous engine/aero damage are named `DRIVER_SLOW_V1` values at
  1 Hz; discrete crash/clutch health states remain in the transition set above.
- A [runtime regression](../tests/AMS2LeagueActivity.Tests/FutureTelemetryRuntimeAdapterTests.cs)
  supplies gear `4 -> 5 -> 4` over 100 ms and confirms all three ordered values survive. Thus short
  discrete changes do not wait for or collapse into the 20-second generic snapshot. The
  [official final-product-v1 report](../work/p024/compact-proof-final-product-v1/p024-machine-report.json) uses 12 five-minute
  DCH frames and retains all 201 generic driver ordinals in the synthetic workload.
- The per-row “New rate / change policy” column retains the analytic class requested by the P023
  inventory. Where the target is generic DCH, this shipping transition/snapshot policy is the actual
  compact cadence. A different cadence or visibility contract requires a new approved policy; it must
  not be inferred from the old P023 tier label.

## Policy decisions and release implications

1. `STATIC` means attempt start plus exact raw change, not periodic duplication. `CHANGE` is the semantic class: named event/replay mappings and the 31-field DCH transition set preserve their declared transitions, while the explicitly documented generic DCH remainder is a 0.05 Hz snapshot and does not claim sub-20-second exactness.
2. `FAST` remains 20 Hz because braking point, throttle-on, steering corrections, speed minima and longitudinal/lateral acceleration depend on it. `MOTION` is 5 Hz with declared quantization; `SLOW` is 1 Hz. Generic DCH uses the explicit 31-field input-cadence transition set plus 0.05 Hz snapshots for the remainder. Those reductions require the separate fidelity report and real-runtime gate to pass.
3. Replay is adaptive: 0.5 Hz progress base, 2 Hz close-battle checks, 5 Hz race-start/incident/end windows, exact position/pit transitions, and 20-second sparse extension context, with browser interpolation. World position is retained through RP keyframes, TG observations and IN bursts; it is never removed.
4. Participant arrays use RP keyframes plus deterministic server diff where a separate event opcode would only duplicate data. Race Story event fields already represented by EV remain exact and are not sacrificed for size.
5. Detailed viewed/root driver values stay local/private in DF/DM/DS/DCH until authoritative owner upload policy permits them. A global/session value must not be hidden in DCH as a workaround because private upload may be denied.
6. The earlier schema-absence blockers are closed: SCH has ordinal/value shape, typed string IDs 1–7 exist, and IN matches its full 45-field semantic catalog. The T2 generic-journal ambiguity is also closed by the declared DCH transition/snapshot policy; the 0.05 Hz remainder is intentionally coarse and is not advertised as exact transition history. The remaining routing boundary is low-rate session text/capability metadata, which stays in lossless legacy JSON/gzip compatibility until typed Session Text mappings are complete. High-rate Story/Replay/Driver/Incident artifacts are A2CT-only.
7. `R104` remains an integrity source: it gates every torn-read-safe SHM snapshot and persists block first/last/anomaly lineage. `R008` is the sole zero-byte useful container.
