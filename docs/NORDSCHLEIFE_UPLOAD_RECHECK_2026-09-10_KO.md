# 노르트슐라이페 미전송 재점검 — 2026-09-10

첨부 진단 문서를 소스·해당 PC의 로그·전송 대기 파일과 대조했습니다. 아래 내용은 현재 로컬 파일을 다시 읽어 확인한 결과입니다. 운영 DB 수신 내역은 조회하지 않았습니다.

현재 수정 결과는 [0.7.0 장거리 저장 보고서](LONG_TRACK_0.7.0_2026-09-10_KO.md)를 참고합니다.

## 결론
**트랙 길이 20,815.41m가 Compact 저장 형식의 20,000m 상한을 초과해 로컬 저장 완료에 실패했고, 그 결과 종료 후 일괄 업로드가 대기 중입니다.** 해당 경기의 결과 요약, 세션 증거, 텔레메트리 모두 전송 시도가 0회이므로 이 경기의 직접 원인을 웹 목록 필터나 HTTP 거부로 설명할 근거는 없습니다.

이번 UI·60Hz 표시 변경은 이 계약의 상한을 수정하지 않았습니다. 따라서 새 테스트 실행 파일에도 이 미전송 문제의 수정은 포함되지 않았습니다.

## 현재 확인값
- 대상 세션: 공개 문서에서 생략 (로컬 진단 원본에 보관)
- 수집 장부 키: 공개 문서에서 생략
- 시도 식별자: 공개 문서에서 생략
- 결과 요약: MULTIPLAYER, 안정된 레이스 결과 관측.
- 세션 증거: MULTIPLAYER, `raceResult.stable=true`.
- 결과 요약 및 증거 큐: 각각 PENDING, attemptCount=0, HTTP 응답 없음.
- 텔레메트리 메타데이터 14개: PENDING 10개, LOCAL_PENDING_OWNER 4개, 전송 시도 합계 0회.
- 종료 장부: closeRequested=true, finalizeAcknowledged=false, durableAck=false.
- knownLossCount=695도 기록돼 있으나, 이 숫자를 모두 복구 불가능한 원본 손실로 해석하지 않았습니다.

## 소스와 오류 대조
C# `CompactTelemetrySchema.cs`와 로컬 웹 개발 소스 `server/cafe24/app/CompactTelemetryProtocol.php` 양쪽에 20km 상한이 있습니다.

| 항목 | 저장 단위 | 현재 정수 상한 | 실제 거리 상한 |
|---|---:|---:|---:|
| trackLengthMeters | 0.01m | 2,000,000 | 20,000m |
| lapDistanceMeters 일반 스트림 | 0.01m | 2,000,000 | 20,000m |
| lapDistanceMeters 참가자 리플레이 | 0.1m | 200,000 | 20,000m |

대상 시도의 실제 오류는 다음 세 종류였습니다.
- trackLengthMeters=2,081,541 → 20,815.41m
- lapDistanceMeters=2,000,216 → 20,002.16m
- 리플레이 lapDistanceMeters=200,101 → 20,010.1m

`RaceUploadCompletionGate`는 안정된 경기 결과와 `finalizeAcknowledged=true`를 함께 확인합니다. 결과 화면이 나왔다는 증거는 있지만, 저장 완료 조건이 충족되지 않아 업로드가 열리지 않은 상태입니다.

서버 소스는 로컬 작업 사본을 확인했습니다. 현재 운영 서버가 이 사본과 같은 파일인지까지 검증한 것은 아닙니다.

## 속도 범위 오류는 다른 시도
같은 실행 로그에 속도 오류가 존재하지만, 위 대상 시도에서는 발견되지 않았습니다. 다른 두 시도의 정수 값은 70,458과 69,076이며, 해당 0.01m/s 단위로 해석하면 704.58m/s와 690.76m/s입니다.

즉, 이번 마지막 경기의 직접 차단 원인과 별도로 구분해야 합니다. 이 속도를 정상 차량 속도로 인정하거나 상한만 무조건 늘리지 않았습니다. 원본·차량 전환·좌표 이동/순간 이상값을 추가로 대조해야 합니다.

## 실패 원본 확인
실패 원본 gzip 7개가 남아 있습니다. 스트리밍 방식으로 전부 압축을 풀어 SHA-256을 계산했고, **7개 모두 파일명에 보존된 원본 해시와 일치**했습니다.

- 압축 파일 합계: 11,777,106바이트.
- 압축 해제 원본 합계: 36,721,012바이트.
- 구성: 운전 텔레메트리 2개, 참가자 리플레이 2개, 세션 메타데이터 3개.
- 원본 JSON을 별도 파일로 풀어 저장하지 않았습니다.
- 이 검증은 파일 무결성 확인입니다. 재인코딩·장부 복원·중복 방지 재전송까지 성공한 것으로 판정하지 않았습니다.

## 수정 시 필요한 범위
1. 트랙 길이뿐 아니라 리플레이·사고·운전 스트림의 모든 거리 상한을 함께 검토해야 합니다. 하나만 바꾸면 다음 스트림에서 다시 실패합니다.
2. 같은 스키마에서 허용 범위를 넓힐지, 새 스키마를 추가할지 호환 정책을 정해야 합니다. 문서가 V1을 불변 레지스트리로 설명하므로 기존 ID를 임의로 재정의하지 않아야 합니다.
3. 서버의 기존/새 데이터 동시 수용을 먼저 검증하고 클라이언트를 배포해야 합니다. 20,000m 경계, 20,815.41m, 더 긴 레이아웃, 범위 초과를 양쪽에서 시험해야 합니다.
4. 보존 원본을 복사한 검증 환경에서 재인코딩한 뒤 완료 장부·중복 식별자·재전송을 검증해야 합니다. 완료 플래그를 수동 변경하거나 저장 완료 조건을 제거하는 방식은 사용하지 않습니다.

이번 요청은 점검이므로 로컬 큐·원본·장부·서버 코드·운영 데이터는 변경하지 않았고 재전송도 실행하지 않았습니다.
