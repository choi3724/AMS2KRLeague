# v0.8.0 — 모니터 기본 출력 경로와 릴리스 검증

## 기준과 근거

- 별도 릴리스 체크아웃 `work/release-0.8.0/repo`는 공개 v0.7.7 `06a92e3c6294db0aade80d6f55c436a2921d3840`에서 시작했다. 분석 트리와 그 미커밋 자료, 기존 설치본은 변경하지 않았다.
- v0.7.7에는 앞선 Codex CLI 작업 중 검증된 페널티 표시, N 눈금 atlas와 문자·정적 상태 재사용, 표시용 그래프 이력이 포함되어 있다. DirectComposition N은 `--monitor-retained-n` 시험 옵션으로만 존재하고 기본 경로가 아니다. 해당 변경만으로 실게임 프레임 저하가 해결됐다는 근거는 없다.
- 분석 트리에 보존된 `work/vr-responsiveness/repo/docs/reports/2026-09-23-common-glass-presentation-candidate.md`의 실제 Client 비교는 동일 DLL·synthetic replay·14개 옵션·전경 GPU helper에서 layered→glass→layered A/B/A를 수행했다. ETW 10~20초 동일 HWND DWM UpdateWindow 간격 p95는 N 일반형 97.236→55.546→97.210ms, 텔레메트리 97.226→55.552→97.217ms, 페달 97.234→55.555→97.208ms였다. ETW lost 0, helper 처리량 71.10→69.97→71.23 frame/s였다. 별도 fixture에서 layered의 `PresentWithGDI → ReadIntoSysMemBuffer → GetRenderTargetData` stack 행은 glass에서 0이 됐다. stack 행은 호출 횟수나 복사 시간이 아니다. 측정 지표는 실제 scanout FPS가 아니며 glass도 16.67ms 예산을 초과한다.

## 제품 변경

`ClientStartupPolicy`가 일반 실행의 DWM glass와 `--monitor-layered` 복구 경로를 선택한다. DWM 구성을 사용할 수 없으면 기존 layered 창으로 자동 복귀한다. `--monitor-layered`는 시험용 `--monitor-retained-n`보다 우선한다. 기존 `--monitor-glass` 인자는 호환된다. 선택은 첫 HUD HWND 생성 전에 이루어지며, 수집·기록·전송·RPM 정책·폰트·이미지·배치 계산과 DComp N 시험 경로는 바꾸지 않았다. 시작 로그에 실제 `dwm-glass` 또는 `wpf-layered` 선택과 복구 사유를 남긴다.

변경 파일: `ClientStartupPolicy.cs`, `App.xaml.cs`, `OverlayWindow.xaml.cs`(설명 주석), `Program.cs` 테스트, 버전 및 릴리스 문서·설치 스크립트. 진단용 replay·helper는 제품에 포함하지 않았다.

## 판정과 한계

확인된 오프라인 전달 개선을 근거로 glass를 기본 출력 경로로 채택한다. 기존 비교 바이너리와 v0.8.0 최종 패키지의 실게임 효과를 동일한 실측 결과로 취급하지 않는다. 실게임·VR 실기기·물리 트리플·혼합 DPI·장시간 점진 저하·물리 화면 60fps는 **NOT TESTED**다. 고부하에서 약55ms p95가 남으므로 Monitor 성능은 **RED**다. 문제 발생 시 `--monitor-layered`로 즉시 이전 경로를 선택할 수 있다.
