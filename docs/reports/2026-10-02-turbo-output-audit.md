# 터보 표시 점검 (2026-10-02)

## 결과

- 0.9.1 계기판의 공유 메모리 읽기 경로는 `mTurboBoostPressure @ 19384`에서 공통 표시 함수와 WPF/Composition 화면으로 연결되어 있다. 그러나 표시 함수가 원시값 `< 100`만 허용해서, 보존된 실제 AMS2 기록의 압력 값은 터보 수치로 표시되지 않았다.
- 공유 메모리 v14의 설치된 `SharedMemory.h`는 이 필드를 `float`, 범위 `0..1+`, 미설정값 `-1`로 설명하지만 단위를 적지 않는다. 보존된 주행 기록(게임 빌드 3398, 3436)은 `MiniChallenge` 최고 197044.094, `TSICup` 최고 193483.750, `KartGX390` 최고 100927.844, `F-Ultimate_Gen1_LD` 최고 14585.820의 원시값을 담고 있다. 비터보 카트도 약 100000을 보이는 점에서 이 값은 터보 부스트만의 수치가 아닌 절대 흡기 압력에 가까운 것으로 추정된다.
- `MiniChallenge`의 동일 세션에서 압력값을 50 Hz 운전 입력과 같은 타임스탬프로 결합했다. 스로틀 1.00, 6148 rpm, 24.3 m/s일 때 197044.1; 스로틀 0.00, 3517 rpm, 22.5 m/s일 때 1127.9였다. 다른 전개 가속 구간도 193000~197000으로 반복됐다. 따라서 이 필드가 실제 주행 중 변화하며 수집됐다는 근거는 있다. 단, 과거 게임 빌드 3436의 기록이다.
- 화면에서는 기록으로 추정한 `원시값 / 100000`을 `bar`로 표시한다. 예: 197044.094 → `1.97 bar`. 헤더의 0..1+ 형태 값도 그대로 지원한다. 이 bar는 **추정된 절대 압력 표시**이며, 대기압을 뺀 게이지 부스트 압력과 같다고 검증하지 않았다. 원본 수집 데이터는 보존한다.

## 테스트 차량과 절차

- **1차 테스트: `Mini Challenge`**. 과거 동일 차량 주행에서 스로틀·압력 변화가 함께 기록되어 재현 목표가 뚜렷하다. **2차 테스트: `Formula Ultimate Gen2`**. [Reiza 개발 업데이트](https://forum.reizastudios.com/threads/automobilista-2-april-2022-development-update.24364/)가 터보 V6와 ERS를 명시한 기본 게임 차량이므로 두 출력을 함께 볼 수 있다.
- AMS2의 `옵션 > 시스템 > 공유 메모리 = Project Cars 2`를 설정한다. 터보 차량을 선택해 연습 세션에 입장하고 확장 N 계기판의 터보 값을 공회전, 부분 가속, 전개 가속, 감속 중 비교한다. 동시에 게임 공유 메모리 원시값과 화면 수치를 기록한다. 값이 동적으로 변하고 화면 표시가 원시값/100000과 일치해야 표시 경로가 통과한 것이다.
- 원본 게임 계기판의 터보 게이지와 수치를 대조해 절대 압력인지 게이지 부스트인지 확인해야 한다. 차량/트랙의 고도 또는 날씨에 따른 대기압 차이도 아직 검증하지 않았다.

## 검증 범위

과거 캡처 분석과 합성값/WPF 경로 테스트를 수행했다. `scripts/verify.ps1`은 Release 빌드 경고 0·오류 0, Client 196/196, Activity 111/111로 완료됐다. WPF 캡처는 `work/validation-20261002-turbo-output/after/avante-turbo-boost-ers-negative-torque.png`에 있다. 조사 중에는 AMS2 프로세스가 실행 중이지 않아 원시값과 화면을 동시 캡처하지 못했다. 이후 사용자가 "터보 출력 잘 됨"이라고 확인했다. 이는 출력 동작에 대한 사용자 확인이며, 사용 빌드·차종·Composition 여부 및 게임 계기판과의 bar 수치 대조는 기록되지 않았다. 미커밋 작업 트리에 있던 토크 정수 반올림 변경은 유지했다.
