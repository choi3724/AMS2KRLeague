# 자동 업데이트 설치 연기 조사 (2026-10-02)

사용자가 보낸 `failure.log`, `failure (1).log`, `failure (2).log`, `새 폴더 (8).zip`을 읽기 전용으로 조사했다. 세 개의 개별 실패 로그는 바이트 단위로 같으며, 모두 “같은 설치 폴더의 다른 오버레이가 실행되어 설치를 연기했습니다.”라고 기록한다. ZIP의 0.7.6, 0.8.3, 0.9.0 실패 시도에도 같은 오류가 있다. 이 세 시도에는 `install.log`가 없어 Inno Setup 실행 전에 중단됐다. 이전의 0.7.3, 0.7.4, 0.7.5, 재시도한 0.7.6, 0.8.1에는 설치 로그가 있다. 가장 최근 `last-result.json`은 0.9.0 설치 실패와 6시간 후 재확인을 기록한다.

0.8.3과 0.9.0에는 각각 같은 설치 경로·버전을 대상으로 한 `update.json`이 두 개 있다. 각 쌍의 부모 프로세스 ID는 서로 다르고 시작 시각 차이는 약 0.152초, 0.177초다. 각 쌍에서 한 도우미는 실패 로그를 남겼고 다른 도우미는 설치 단계에 도달하지 않았다. 현재 코드에서 두 번째 도우미가 업데이트 뮤텍스를 얻지 못하면 준비 파일도 남기지 않고 종료하며, 그 앱은 계속 실행될 수 있다. 따라서 거의 동시에 시작된 두 클라이언트가 서로의 업데이트를 막았다는 설명이 기록 및 코드와 맞는다. 다만 종전 오류에는 차단 PID와 프로세스 경로가 없고, 기존 코드가 경로를 읽지 못한 다른 `AMS2LeagueClient` 프로세스도 차단하므로 실제 차단 대상을 이 자료만으로 확정할 수 없다.

수정: 같은 설치 경로의 앱이 중복 시작되지 않도록 명명된 뮤텍스를 앱 시작부터 종료까지 유지한다. 다른 설치 경로에는 영향을 주지 않는다. 업데이트 도우미가 앱 프로세스 때문에 중단할 때는 실패 로그에 차단 PID와 경로 확인 결과를 기록한다. 경로를 읽지 못하는 프로세스는 보수적으로 설치를 연기하며 별도 문구를 남긴다. 원본 첨부 파일은 수정하지 않았다.

검증: 변경 전 전체 검사는 Release 빌드 0경고/0오류였으나 기존 계기판 시각 테스트 1건에서 중단됐다. 변경 후 첫 전체 검사는 Client 197/197, Activity 111/111 통과했다. 이후 설치 차단 재현 테스트를 추가했고, 실제 동일 이름의 실행 파일을 남긴 상황에서 `failure.log`에 차단 PID가 기록되고 설치 프로그램이 시작되지 않는 것을 확인했다. 동일 경로 중복 획득 거부와 다른 경로 허용도 검사했다. 최종 전체 검사도 Release 빌드 0경고/0오류, Client 197/197, Activity 111/111 통과했다. 근거는 `work/validation-20261002-updater-final/`에 기록했다. 사용자 PC에서의 실제 업데이트 성공은 미확인이다.

영향받는 사용자에게는 모든 `AMS2LeagueClient.exe` 프로세스를 종료한 후 앱을 한 번만 실행해 재시도해야 한다. 이전 실패의 6시간 재확인 대기와 받은 ZIP에 설치 파일이 남아 있지 않은 점을 고려하면, 즉시 복구에는 현재 릴리즈 설치 파일을 별도로 받아 실행하는 방법이 필요하다. 현재 재설치 버전은 사용자 확인을 기다리고 있다.
