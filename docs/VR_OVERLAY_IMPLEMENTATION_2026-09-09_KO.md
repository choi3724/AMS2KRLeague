## 구현 결과

기존 실행파일 하나에서 상태창의 **모니터·VR 표시 설정**을 열어 다음 모드를 선택한다.

- 모니터 표시(기본)
- VR 표시
- 모니터 + VR 동시 표시

VR 패널의 너비·거리·좌우·상하·좌우 각도·상하 각도를 저장하고 즉시 적용한다.
고개 추종과 공간 고정을 선택할 수 있으며 정면 재설정 버튼으로 고정 기준을 다시 잡는다.
개별 패널의 2D 배치는 기존 레이아웃 편집을 사용한다. VR 안에서는 여러 HUD를 하나의 투명한 패널로 합성한다.
패널마다 서로 다른 3D 깊이를 지정하거나 VR 컨트롤러로 편집하는 기능은 포함하지 않았다.

게임 없는 주행·대기 미리보기도 VR이 연결되면 표시할 수 있다.
편집 테두리는 VR 이미지에 포함하지 않는다.
VR 전용 모드에서는 모니터 HUD의 투명도를 0으로 두되 화면을 계산할 WPF 배치는 유지한다.
레이아웃 편집 중에는 모니터에서 조작할 수 있도록 다시 보이게 한다.

## 지원 범위와 연결

이번에 구현한 연동은 **SteamVR / OpenVR**이다.
특정 헤드셋 모델을 코드로 제한하지 않지만, 모든 기종에서 실제 동작을 확인했다는 뜻은 아니다.

Meta/Oculus 직접 실행 및 SteamVR을 거치지 않는 OpenXR/OpenComposite 경로는 현재 미지원이다.
지원되지 않는 경로를 동작한다고 표시하거나 실행 환경을 자동으로 바꾸지 않는다.
실행 중인 SteamVR과 헤드셋을 확인해 연결하며, 프로그램이 SteamVR을 대신 실행하지 않는다.
연결 실패나 종료는 상태창과 `VR_STATUS` 로그에 남기고 5초 간격으로 재시도한다.
모니터 모드로 전환하거나 앱이 종료되면 오버레이 핸들과 OpenVR 연결을 정리한다.

SteamVR의 현재 장면 프로세스가 AMS2 프로세스와 일치하는 경우에만 실제 경기 HUD를 보낸다.
이 경우에는 모니터 창의 전면·최소화 조건을 VR 표시에서만 우회한다.
다른 VR 앱으로 바뀌면 이미지 제출 직전에 프로세스를 다시 대조해 숨긴다.
사용자가 직접 연 레이아웃 미리보기는 이 실제 경기 조건과 구분한다.

실제 헤드셋으로 연결·표시·종료·재접속·게임 전환을 확인한 상태는 아니다.
현재 연결 수명 주기 검증은 가짜 런타임을 사용하는 자동 테스트다.

## 렌더링과 부하

WPF 패널을 투명한 RGBA 이미지로 합성하고 OpenVR의 `SetOverlayRaw`로 전달한다.
Valve 공식 API는 바이트 이미지 업로드와 오버레이 텍스처를 제공한다.
[고정 버전 공식 헤더](https://github.com/ValveSoftware/openvr/blob/0924064316de3effbcd1acf1e309182a2deb1c05/headers/openvr.h)

- 긴 변 최대 1,280픽셀, 최대 15fps.
- 미완료 이미지 제출은 한 장만 유지한다. ImageLoaded 응답 또는 연결 정리까지 버퍼를 유지한다.
- 3초 동안 이미지 응답이 없으면 연결을 정리하고 재시도한다.
- 1,280×720 샘플의 원시 이미지 버퍼는 3,686,400바이트다.
- 이 버퍼는 **같은 PC의 SteamVR 표시용**이다. 웹서버에 이 이미지를 업로드하지 않는다.
- 최종 전체 테스트의 합성 비용: 15회 평균 **20.19ms/프레임**.
- 다른 검증 실행에서는 약 21~27ms였다. 실제 SteamVR 이미지 전달 비용과 게임 FPS 영향은 포함하지 않은 수치다.
- 네이티브 텍스처 직접 제출을 사용하는 GPU 최적화는 포함하지 않았다.

합성 과정에서 내용의 잉크 영역에 맞춰 숫자가 확대되던 문제를 확인했고,
원래 패널의 실제 표시 영역을 명시하여 수정했다. 수정 후 합성 이미지와 설정 화면을 확인했다.

## 수집·서버 전송과의 관계

기존 게임 데이터 수집은 별도의 읽기 타이머에서 계속 실행한다.
이번 작업은 표시 방식만 변경하며 결과 JSON, raceMode, gzip 협상, 업로드 시점 및 수집 범위를 변경하지 않았다.
새로운 VR 미리보기 데이터가 수집 엔진에 들어가는 경로도 추가하지 않았다.
실제 게임에 추가되는 CPU/GPU 부하가 없는 것으로 단정하지 않으며 실기기 테스트에서 확인해야 한다.

설정은 기존 `%LOCALAPPDATA%\AMS2KRLeague\overlay-layout.json`의 `vrHud`에 저장한다.
이전 파일에 vrHud가 없으면 모니터 모드로 동작한다. 값은 범위를 검증한다.
기본 레이아웃 복원은 VR 표시 모드와 거리 설정을 보존한다.

## 공식 SDK와 패키지

OpenVR SDK **2.15.6** / 커밋 `0924064316de3effbcd1acf1e309182a2deb1c05`를 고정했다.
공식 C# 바인딩과 x64 DLL을 사용하며, 배포 라이선스를 함께 넣는다.
[Valve OpenVR 저장소](https://github.com/ValveSoftware/openvr/tree/0924064316de3effbcd1acf1e309182a2deb1c05)

출처와 파일별 SHA-256은 `src/AMS2LeagueClient/ThirdParty/OpenVR/README.md`에 기록했다.
게임 DLL 주입·게임 파일 변경·입력 가로채기·전역 단축키는 사용하지 않는다.

시험판 ZIP: `artifacts/AMS2-League-Overlay-0.5.1-vr-test-20260909-win-x64.zip`.
자체 .NET 런타임과 VR 라이브러리를 포함하므로 압축을 모두 푼 뒤 기존과 같은 `AMS2LeagueClient.exe`를 실행한다.
별도 보조 실행파일을 사용하지 않는다.
사용법과 실기기 점검표를 함께 제공한다.

+vr-test.20260909는 빌드 식별자다. 기존 SemVer 비교에서 0.5.1과 같은 우선순위로 처리되어
현재 0.5.1 릴리스로 자동 교체되지 않는다. 소스의 공식 릴리스 버전은 변경하지 않았다.

## 남은 실제 기기 검증

VR 사용자에게 함께 제공한 점검표로 다음을 확인받아야 한다.

1. 헤드셋 기종·연결 방식·SteamVR 버전·AMS2 실행 경로.
2. 투명 배경, 글자 가독성, 색상과 이미지 방향.
3. 모니터/VR/동시 표시 및 게임 창 후면·최소화.
4. 위치·거리·각도·고개 추종·공간 고정·정면 재설정.
5. SteamVR 종료, 헤드셋 분리·재연결, 다른 VR 앱으로 전환.
6. VR 켜기 전후 게임 프레임과 오버레이 갱신 지연.

서버 코드와 다른 작업의 문서는 수정하지 않았다. 기존 미커밋 gzip·레이아웃 변경을 보존했다.
