# R11/R12 기록 누락 조사 및 로컬 수정 (2026-10-07)

이 문서는 2026-10-06 경기의 이 PC 원본, 업로드 대기 상태, 읽기 전용 관리자 화면을 구분해 기록한다. 운영 DB 변경, 기존 대기 항목 재전송, 설치, 배포는 수행하지 않았다.

R11 로그는 정상 랩 완료 때 `RACE_RESTART_SIGNAL`이 20회 발생했다. 기존 `IsRestart`는 랩마다 0으로 돌아가는 `mCurrentTime`을 세션 시간처럼 사용했다. 이를 제거하고 실제 재시작 신호와 세션 전환을 기존 판정에 맡겼다.

두 경기 퀄리파잉과 레이스의 `eventFingerprint`는 같지만 `captureSessionId`와 `sessionFingerprint`는 달랐다. 전환 간격은 각각 약 0.300초였다. 예선·레이스 witness의 참가자 이름+차량+클래스가 R11 15명, R12 10명 일치했다. 기존 업로드 완료 게이트는 같은 capture ID에 완료된 레이스 결과와 durable finalize ACK가 함께 있어야 열렸다. 새 게이트는 같은 소스 클라이언트·이벤트·서킷·클래스·겹치는 참가자·시간 순서를 확인하여 **새로 캡처한** 이전 예선 witness만 연결한다. 구버전 대기 항목은 로컬 정책 표시와 활성화 시각으로 자동 전송을 막는다. 압축 기록은 해당 phase 자신의 durable finalize ACK가 있을 때만 허용한다. R11의 앞선 6행 witness는 뒤따른 17행 기록에 대체된 것으로 판정하여 열지 않는다.

속도 오류는 드문 단일 샘플만의 문제가 아니다. 실패한 원본 청크를 복사본으로 검사했을 때, R11 replay 청크 2개에 범위 초과 속도 행이 114개와 783개, incident 청크 2개에 1,330개와 9,564개 있었다. R12는 replay 226개, incident 2,748개였다. 원본 값과 행 번호를 로컬 압축 JSON 및 진단 sidecar에 보존하고, 전송용 압축 레코드에서는 표현 불가능한 속도 필드만 null로 표시한다. 랩/위치 등 다른 필드는 유지하며 손실 수를 ledger에 적어 PARTIAL로 확정한다. 허용 범위를 늘리거나 임의 수치로 보정하지 않는다.

서버 소스의 관리자 조회는 참가자 사전을 인원수의 근거로 사용하고, 시간·실제 참가자·고유한 서킷 후보가 일치하는 메타데이터 없는 리플레이를 같은 경기의 보기 결과에만 결합한다. 원본 DB 행은 수정하지 않는다. 근거가 모호하거나 참가자/서킷을 확인할 수 없는 미완성 그룹은 공식 관리자 결과 목록에서 제외한다.

## 검증과 제한

- 전체 로컬 검증: Release 빌드 경고/오류 0, 클라이언트 199/199, 캡처·압축 기록 114/114. 정상 랩 완료/실제 재시작, 호스트·참가자 phase witness, 중단 경기, 대체된 임시 기록, 앱 재실행 후 디스크 대기열 복구, 비정상 속도 격리와 원본 보존을 테스트했다.
- 앞선 서버 `web06.php` 62/62 통과 및 PHP 문법 검사 결과는 당시 수정 범위의 기록이다. 이후 작업 트리에 추가된 예선 전용 `QualifyingWitnessRecovery.php`와 해당 테스트는 현재 PC에서 PHP 실행기를 찾지 못해 이번 검증에서 실행하지 못했다. 서버 검증은 **PARTIAL**이다. 별도 `web05.php` 실행은 이번 변경 파일 밖의 `PortalView::driverRaceDetail(null)`에서 실패했으며 이번 작업에서 해결하지 않았다.
- 복사본 대기열 오프라인 판정: 실제 구버전 대기열의 R11 6행·17행 및 R12 13행 witness는 모두 자동 전송 차단, `GetDueBatch=0`. 별도 메모리상의 대상별 승인 가정에서만 17행·13행 witness가 허용되고 6행과 두 퀄리파잉 압축 기록은 계속 차단된다. 원본과 복사본의 파일 해시는 모두 일치했다.
- 실제 AMS2 재경기, 실제 네트워크 전송, 서버 배포 후 화면 검증은 수행하지 않았다. 기존 두 퀄리파잉의 서버 등록과 위 세 그룹의 운영 화면 정리는 아직 완료되지 않았다.

## 기존 원본의 안전한 복구 경계

R11·R12의 17행/13행 witness 및 메타데이터 15개/3개 원본은 로컬에 남아 있어 검토 대상이다. 다만 퀄리파잉 압축 시도는 원래 finalize ACK가 없고 여러 청크에 범위 초과 값이 있으므로 현재 파일을 자동 재전송해서는 안 된다. 별도 복사본에서 속도 필드만 누락 처리한 청크별 후보와 원본 값·행 번호를 만들었지만, 전체 확정 ACK가 없으므로 전송 가능 패키지로 간주하지 않는다. 서버 기존 원본과 해시·경기 ID 중복 여부는 아직 운영 DB에서 확인하지 못했다. 연습은 진행하지 않았으므로 복구 대상이 아니다. 대상별 판정은 [전송 전 확인표](R11-R12-transfer-checklist-2026-10-07.md)에 적는다.
